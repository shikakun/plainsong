- （）：画面の文言のうち、値が入るところ（例：「（数）文字」）

## 1 概要

Plainsongは、プレーンテキストで文章を書くこと、読むことに特化したテキストエディタで、「文章を書きたくなるテキストエディタ」を掲げています。Plainsongに書いたテキストは、ファイルに保存しなくても下書きとして残り、本文を空にしないかぎり、再起動しても復元できます。文字サイズ、行間、フォント、組方向（横書き・縦書き）、罫線や原稿用紙をモチーフにしたガイドを表示するかどうかなど、ユーザーの執筆スタイルに合わせて柔軟にカスタマイズできます。macOS 26以降で動作し、Mac App Storeで無料で配布しています。バンドルIDは`com.shikakun.plainsong`、カテゴリは仕事効率化で、日本語（開発言語）と英語に対応しています。

アプリケーションはApp Sandboxで動き、ユーザーが選んだファイルの読み書きと印刷だけを許可しています。ReleaseビルドではHardened Runtimeを有効にしています。暗号化は使っておらず、`ITSAppUsesNonExemptEncryption`は`false`です。データの収集やトラッキングはしません。プライバシーマニフェストで申告しているRequired Reason APIは、UserDefaults（`CA92.1`）とファイルのタイムスタンプ（`C617.1`、`3B52.1`）です。

Plainsongはオープンソースプロジェクトです。ソースコードはApache License, Version 2.0、アプリケーションのアイコンなどの画像はクリエイティブ・コモンズ 表示 - 非営利 - 改変禁止 4.0 国際 ライセンスのもとで公開しています。このテキストエディタが、誰かの創作の役に立てたら嬉しいです。

### 1.1 扱えるファイル

| 種類 | UTI | 拡張子 |
| --- | --- | --- |
| プレーンテキスト | `public.plain-text` | `.txt`など |
| Markdown | `net.daringfireball.markdown` | `.md`、`.markdown` |
| MDX | `com.shikakun.plainsong.mdx` | `.mdx` |

MarkdownとMDXのUTIはアプリケーションで宣言しています。どれも`CFBundleTypeRole`は`Editor`、`LSHandlerRank`は`Alternate`で、他のアプリケーションに代わって既定のアプリケーションになることはありません。中身はどれも同じプレーンテキストとして扱い、拡張子が`.mdx`のファイルだけ、Markdownの記法をMDXとして読みます（[8章](#8-markdownの記法の強調)）。

## 2 アプリケーション

### 2.1 起動

起動すると、アプリケーションをアクティブにして、すべての下書きを作成日時の古い順に開きます。下書きがひとつもなければ、新しい下書きを作ります。状態の復元で残っていたウィンドウと、Finderなどから開いたファイルも、あわせて開きます。

ログイン項目として起動したときは、ウィンドウを開かずに待機し、ユーザーがDockやメニューバーのアイコンからPlainsongを呼び出したときに下書きを開きます。ログイン時に起動したかどうかは、起動を終えたときに、起動のApple Eventで確かめます。前回問い合わせたログイン項目の状態が有効でなければ、確かめるのを待たずにウィンドウを開きます。

Dockのアイコンをクリックすると、表示されている本文のウィンドウのうち、いちばん手前のものをキーウィンドウにします。本文のウィンドウがひとつも表示されていなければ、下書きのウィンドウを開き直します。

### 2.2 アプリケーションがアクティブでなくなったときと終了するとき

アプリケーションがアクティブでなくなると、すべての書類の変更を保存します。下書きは全文をスナップショットにまとめます。ファイルは、自動保存が「しない」以外の設定なら、まだ自動保存していない変更を保存します。このとき、保存できない文字があってもダイアログは出しません。

アプリケーションはSudden Terminationに対応しています。ファイルに保存していない変更（「ファイルに上書き保存」では、自動保存していない変更）がある書類が開いているあいだだけ、Sudden Terminationを無効にします。

### 2.3 アイコンの表示場所

設定の「アイコン」で、アイコンを表示する場所を「Dockに表示」「メニューバーに表示」「両方に表示」から選べます。メニューバーだけに表示するときは、Dockにもアプリケーションの切り替えにも表示しません。表示場所を切り替えたときにアプリケーションがアクティブなら、アクティブなままにします。

メニューバーのアイコンをクリックすると、アプリケーションをアクティブにし、Dockのアイコンをクリックしたときと同じように本文のウィンドウを表示します。右クリックか、controlキーを押しながらクリックすると、「設定…」と「Plainsongを終了」のメニューを出します。VoiceOverでは、アイコンを「Plainsong」と読み上げます。

### 2.4 ログイン時に起動

設定の「ログイン時に起動」で、ログイン項目（`SMAppService`）への登録と解除を切り替えます。システム設定での許可が必要な状態では、チェックボックスをオンにしたまま「システム設定で許可が必要です」と表示します。「システム設定を開く」のリンクを押すと、システム設定の「ログイン項目と機能拡張」を開きます。ログイン項目の状態は、設定ウィンドウがキーになるたびに問い合わせ直します。

### 2.5 表示言語

設定の「言語」で、「システム言語」「English」「日本語」から表示言語を選べます。「システム言語」はmacOSの言語設定に従います。表示言語は起動したときに決まるので、今の表示言語と違う言語を選ぶと、「再起動が必要です」のシートで「言語の変更を反映するにはPlainsongを再起動してください。」と知らせます。「今すぐ再起動」を押すと、下書きを保存してからアプリケーションの新しいインスタンスを起動し、起動できたら今のインスタンスを終了します。「あとで」か⎋キーでシートを閉じます。設定ウィンドウがキーになるたびに、選んでいる言語を表示し直します。

## 3 書類

書類には、ファイルに結び付いていない「下書き」と、ファイルを開いたり保存したりした「ファイル」の2種類があります。

### 3.1 下書き

⌘Nで作る書類も、「複製」で作る書類も下書きになります。下書きは、自動保存の設定にかかわらず、編集するたびにアプリケーションのフォルダへ保存します（[17.2節](#172-下書きの保存形式)）。閉じるときや終了するときに、保存を確かめるダイアログは出しません。ウィンドウのタイトルは画面に表示しませんが、VoiceOverで読み上げ、「ウインドウ」メニューにも表示します。

下書きを閉じても、内容は残ります。ただし、本文が空で、他にも下書きがあるときは、その下書きを削除します。最後の1つは、空でも残します。状態の復元では、ウィンドウに記録した下書きを開き直し、その下書きがすでになければウィンドウを復元しません。

下書きで「保存」を選ぶと、保存パネルを出します。名前の欄には、本文の最初の空でない行から前後の空白を除いた、先頭の30文字を入れます。`/`と`:`は`-`に置き換え、先頭の`.`は取り除きます。ファイルに保存すると下書きを削除し、その書類はファイルの書類になります。

### 3.2 ファイル

ファイルの書類は、ウィンドウのタイトルにファイル名とプロキシアイコンを表示します。保存の確認、バージョン、名前の変更、移動は、NSDocumentの標準の振る舞いに従います。

保存パネルには、ファイルフォーマットを選ぶメニューを出しません。保存パネルで拡張子を書き換えると、Markdownの記法の読み方もその場で切り替わります。ファイルを読み直したときは、取り消しの履歴を消します。

### 3.3 自動保存

設定の「自動保存」で、ファイルの書類を自動保存する方法を3つから選べます。下書きはこの設定の影響を受けません。

「しない」では、自動保存をしません。「保存するまでバックアップを残す」（デフォルト）では、元のファイルを書き換えずに、15秒ごとにバックアップのフォルダへ書き込みます。バックアップのファイル名は元のファイルと同じで、すでにあれば「名前 2.txt」のように番号をつけます。ファイルに保存すると、バックアップは消えます。この2つの設定では、変更を保存しないまま閉じたり終了したりするときに、保存を確かめます。「ファイルに上書き保存」では、macOSの自動保存の仕組みで、ファイルに直接書き込みます。

設定の「バックアップのフォルダを開く」は、「保存するまでバックアップを残す」のときだけ表示し、フォルダをFinderで開きます。フォルダがなければ、作ってから開きます。

自動保存の設定によって、「ファイル」メニューの項目が変わります（[14.2節](#142-ファイル)）。設定を変えると、開いているすべての書類とメニューにすぐ反映します。

### 3.4 文字エンコーディング

ファイルを読み込むときは、次の順に文字エンコーディングを判定し、最初に読めたものを使います。

1. BOMつきのUTF-8、UTF-16 LE、UTF-16 BE
2. BOMなしのUTF-8
3. 拡張属性`com.apple.TextEncoding`が示す文字エンコーディング（値は`SHIFT_JIS;2561`のように、IANAの名前とCFStringEncodingの値を並べたもの）
4. システムによる推測（Shift_JIS、EUC-JP、ISO-2022-JP、UTF-16を候補とし、読めない文字の置き換えは許さない）

いずれでも読めなければ、ファイルを開けないエラーになります。

保存するときは、読み込んだときの文字エンコーディングとBOMの有無を保ちます。UTF-8以外で保存したときは、保存のたびに拡張属性`com.apple.TextEncoding`をつけます。バックアップにはつけません。

保存できない文字が含まれるときは、文字を置き換えずに保存を止め、「このテキストには、（文字エンコーディング）で保存できない文字が含まれています。UTF-8で保存すると、すべての文字を保存できます。（文字エンコーディング）のまま保存するには、キャンセルして、保存できない文字を削除してください。」と知らせます。「UTF-8で保存」を選ぶと、文字エンコーディングをUTF-8に変えて保存し直し、「キャンセル」を選ぶと保存しません。入力が止まったときの自動保存では、このダイアログを出さずに保存を見送り、⌘Sを押したときや閉じるときに知らせます。バックアップへの自動保存では、保存できない文字があればUTF-8で書き込みます。

文字エンコーディングは、ステータスバーなどには、次の名前で表示します。

| 文字エンコーディング | 表示 |
| --- | --- |
| UTF-8 | `UTF-8`、BOMつきは`UTF-8 BOM` |
| UTF-16 | BOMつきは`UTF-16 LE`か`UTF-16 BE`、システムの推測で判定したものは`UTF-16` |
| Shift_JIS、CP932、Windows-31J | `Shift-JIS` |
| その他 | IANAの名前。なければシステムのローカライズ名 |

### 3.5 改行コード

ファイルを読み込むと、LF、CRLF、CRのうち、もっとも多く使われているものをそのファイルの改行コードとします。LFと同数のときはLFに、CRLFとCRが同数のときはCRLFにします。本文は読み込んだときの改行をそのまま保ち、保存するときにファイルの改行コードへそろえます。returnキーで入れる改行と、置換で入れる文字列に含まれる改行も、ファイルの改行コードにします。

改行コードが混在するファイルを開いたり読み直したりすると、そのウィンドウがキーになったときに、「このファイルには、異なる改行コードが混在しています」のシートで「保存するときに、もっとも多く使われている（改行コード）にそろえます。」と知らせます。シートで今後表示しないことを選ぶと、以降は表示しません。

### 3.6 他のアプリケーションによる変更

他のアプリケーションがファイルの更新日時を変えても、中身が最後に読み書きした内容か、保存している途中の内容と同じなら、書類の更新日時を合わせるだけにします。中身が変わっていれば、NSDocumentの標準の振る舞いに従います。この確認は、保存する前にも行います。

## 4 エディタのウィンドウ

ウィンドウの初期の大きさは640×480ptです。新しく開くウィンドウは、最後に大きさを変えたか閉じたウィンドウの大きさに合わせます。全画面表示のあいだの大きさは記録しません。他に本文のウィンドウが表示されていれば少しずらして重ね、表示されていなければ画面の中央に開きます。

タイトルバーは透明で、区切り線を引きません。ツールバーの項目がなければ、ツールバーも表示しません（[11.1節](#111-ツールバー)）。縦書きでウィンドウの幅を変えたときは、右端の列を動かしません。全画面表示にできます。ウィンドウをタブにまとめることはできません。

### 4.1 入力

書類を開くと、カーソルを本文の末尾に置き、そこが見えるように表示します。本文はプレーンテキストだけを扱い、リッチテキストや画像は受けつけません。スペルチェック、文法チェック、スペルの自動修正、スマート引用符、スマートダッシュ、テキストの置換、リンクとデータの自動検出、テキストの補完、スマートな挿入と削除、インラインの予測入力、作文ツールは、すべて無効にしています。

取り消しとやり直しには、書類ごとの履歴を使います。取り消しとやり直しで戻った文字は、今の設定の書式で表示します。設定を変えて本文全体の書式が変わっても、取り消しの履歴には入りません。

組方向を切り替えるとき、置換するとき、ファイルを読み直すときは、変換中の文字を取り消します。

### 4.2 余白

本文の余白は、設定の文字サイズをもとに決めます。上の余白は、タイトルバーとツールバーの高さに文字サイズを足した大きさで、全画面表示でタイトルバーが隠れても変えません。下の余白は、ステータスバーの高さと文字サイズの大きいほうに、文字サイズを足した大きさです。横書きでは、行頭と行末の余白は文字サイズの2倍を最小とします。縦書きでは行頭が上、行末が下になり、上下の余白がそのまま行頭と行末の余白になります。左右の余白は文字サイズの2倍です。

番号を表示するときは、文字サイズの4倍の幅の欄を行頭の側に置き、行頭の余白を、最小の余白に欄の半分の幅を足した大きさにします。

「読みやすい幅で折り返す」をオンにしたときは、行頭と行末に同じ余白を空けて、行を中央に置きます。その余白が最小の余白に満たないときは、行頭を最小の余白にして、行末の余白を広げます。行末の余白が最小の余白より広がったときは、行と交わる方向（横書きでは上下、縦書きでは左右）の余白も、広がった分の半分だけ、文字サイズの4倍を上限に広げます。ただし原稿用紙では、マスの数が「折り返す幅」の上限に達しているときだけ広げます。

余白が変わったときに本文の先頭か末尾を表示していれば、広がった余白が見えるようにスクロールし直します。

## 5 組版

### 5.1 文字サイズ

文字サイズは、12、14、16（デフォルト）、18、21ポイントの5段階から選べます。

### 5.2 行間

行送りは1行の高さに対して、「コンパクト」では1倍、「標準」（デフォルト）では1.5倍、「ゆったり」では2倍です。1行の高さは、フォントにかかわらず、ゴシック体の欧文の行の高さにそろえます。

カーソルと選択範囲のハイライトは、行間を含めない1行分の高さにし、和文の字面の中心に合わせます。

### 5.3 フォント

| フォント | 欧文 | 和文 | 太字 |
| --- | --- | --- | --- |
| ゴシック体（デフォルト） | システムフォント | ヒラギノ角ゴシック W4 | システムフォントの太字、ヒラギノ角ゴシック W7 |
| 明朝体 | システムのセリフ体 | ヒラギノ明朝 ProN W3 | セリフ体の太字、ヒラギノ明朝 ProN W6 |

和文は、macOSの言語設定にかかわらず、常にヒラギノで表示します。Markdownのコードなどの等幅の文字には、システムの等幅フォントとヒラギノ角ゴシック W4を使います。タブ幅は文字サイズの2倍です。

### 5.4 組方向

「横書き」（デフォルト）と「縦書き」から選べます。縦書きでは、右の列から左へ進みます。

縦書きでは、半角の英数字を次の規則で組みます。半角の英数字と記号が続く語のうち、2桁の数字は縦中横にします。1文字の英数字と、数字と大文字だけからなり大文字を含む語は、全角の字形に差し替えて1字ずつ正立させます。それ以外の語（小文字を含む2文字以上の語、3桁以上の数字など）は、横に倒したまま組みます。Markdownのコードと等幅で表示する記号、変換中の文字には、この規則を当てはめません。

### 5.5 カーニング

設定の「カーニング」がオフ（デフォルト）のときは、字間を0に固定します。欧文のカーニングだけでなく、和文の約物の詰めや和欧間のアキもなくなります。オンのときは、字詰めをTextKitに任せます。ただし縦書きでは、1.5字分に広がる句読点（、。，．）を1字分の字送りに戻し、正立させた英数字と縦中横の字間は0に固定します。終わり括弧が続くところと段落の末尾の句読点は、TextKitの詰めのままにします。

原稿用紙のガイドではカーニングを使わず、設定でもメニューでも切り替えられません。

### 5.6 読みやすい幅で折り返す

設定の「読みやすい幅で折り返す」がオフ（デフォルト）のときは、ウィンドウの幅いっぱいで折り返します。オンのときは、「折り返す幅」で選んだ長さを上限に折り返します。

| 折り返す幅 | 行の長さ |
| --- | --- |
| デフォルト | 縦書きでは「日本語の20字程度」。横書きでは、表示言語が日本語なら「日本語の40字程度」、それ以外なら「英語の66字程度」 |
| 英語の66字程度 | 文字サイズの29倍 |
| 日本語の40字程度 | 文字サイズの40倍 |
| 日本語の20字程度 | 文字サイズの20倍 |

原稿用紙のガイドでは、この字数が1行のマスの数の上限になります。

### 5.7 段落

設定の「段落の間に余白を空ける」をオンにすると、段落のあとに「余白の大きさ」で選んだ余白を空けます。大きさは1行の高さに対して、「1行の半分」（デフォルト）、「1行分」、「2行分」から選べます。この設定はガイドが「白紙」のときだけ使え、罫線と原稿用紙では余白を空けません。

設定の「段落の先頭を字下げする」をオンにすると、段落の1行目を「字下げの幅」で選んだ幅だけ下げます。「全角1文字分」は文字サイズと同じ幅、「ハードタブ1文字分」は文字サイズの2倍の幅です。「デフォルト」は、表示言語が日本語なら全角1文字分、それ以外ならハードタブ1文字分になります。ただし、次のような段落は字下げしません。

- 和文の始め括弧（`「『（〔［｛〈《【〘〖〝｟⦅`）で始まる段落。欧文の括弧や引用符で始まる段落は字下げします
- 空白で始まる段落
- Markdownの見出しやリストなど、記法の表で字下げしないとした行（[8.2節](#82-記法)）
- U+2028（LINE SEPARATOR）のあとの行

字下げは表示だけを変え、本文に空白を入れることはしません。

### 5.8 ぶら下げ

設定の「行末の句読点をぶら下げる」がオン（デフォルト）のときは、行末からあふれた句読点を、行の外に出して組みます。ぶら下げるのは全角の`、。，．`で、半角の`.,`はぶら下げません。句読点のあとに行頭に置けない字が続くときは、ぶら下げません。テキストコンテナは、ぶら下げる分として行の長さより1.25字分長くとります。選択範囲のハイライトは、版面の端か、ぶら下げた字の端で止めます。

### 5.9 禁則処理

原稿用紙のガイドでは、Plainsongが行を区切る位置を決め、1字ずつマスに組みます（[6.3節](#63-原稿用紙)）。それ以外では、ぶら下げを除いて、TextKitの禁則処理と単語の折り返しに任せます。

原稿用紙の禁則文字は、[stone_engine](https://github.com/ndc-stone/stone_engine)（MIT License, Copyright 2024 Nihon Design Center）の`STKinsoku`で定義されている文字をもとに、全角の`！，．：；`と`ゝゞ`を加えたものです。


## 6 ガイド

設定の「ガイド」で、本文の背景に引く線を「白紙」（デフォルト）、「罫線」、「原稿用紙」から選べます。

### 6.1 線の描き方

線の色は、テーマの`foreground`（テーマになければ`labelColor`）を18%の不透明度にしたものです。アクセシビリティの「コントラストを上げる」がオンなら、55%にします。線は1物理ピクセルの太さで、ピクセルの境界に合わせて引きます。線は本文のクリックをさまたげません。

罫線と原稿用紙では、行送りを、1行の高さと行間の倍率で決まる一定の間隔にし、段落の間の余白は空けません。

### 6.2 罫線

ノートの罫線のように、行と行の中間に線を引きます。1行目の前には引きません。本文の末尾より先も、行送りの間隔でウィンドウの端まで引きます。線の長さは行の長さと同じです。

### 6.3 原稿用紙

ページの区切りのない、ひと続きのマス目を引き、1字を1マスに組みます。縦書きと横書きの両方で使えます。マスは文字サイズを一辺とする正方形で、行送りの間隔で並べます。1行のマスの数は、行の方向の長さから最小の余白を除いた長さに入るだけの数（少なくとも1マス）で、マス目は行頭の側にそろえます。「読みやすい幅で折り返す」がオンなら、「折り返す幅」の字数を上限にします。

本文全体を和文のフォントで組みます。Markdownの記法の強調とカーニングは使いません。

Swiftの`Character`（書記素クラスタ）を1字として数え、次の規則でマスに置きます。

- 字送りが1字分でない字は、1マスに収まるよう字送りを固定したフォントに差し替えます。対象は、基本ラテン文字、ダッシュ・三点リーダー・引用符など、半角カナ、macOSのフォントで全角の幅にならない字です。絵文字は文字サイズの0.85倍にします
- 縦中横にする2桁の数字は、横書きでも1マスにまとめます。行が語の途中から始まるときは、2桁とみなしません
- 半角カナと、それに続く半角の濁点・半濁点は、1マスにまとめます
- タブは、次の2マスの倍数の位置まで進めます
- 制御文字、書式文字、結合文字などの幅のない字は、マスを使いません
- 字下げは、全角1文字分なら1マス、ハードタブ1文字分なら2マスを、段落の先頭に空けます。字下げしない段落は[5.7節](#57-段落)と同じです

行に入りきらない字は、次の行へ送ります。ぶら下げがオンで、あふれた字がぶら下げられる句読点なら、行の外の1マスに置きます。そうでなければ、行頭禁則文字と行末禁則文字を避けて前へさかのぼって行を区切り、区切れる位置がなければマスの数で区切ります。

## 7 改行・空白・番号の表示

### 7.1 改行と空白

設定の「改行を表示」をオンにすると、改行の位置に段落記号（¶）を描きます。空の段落の記号は、字下げせずに行頭に描きます。

設定の「空白を表示」をオンにすると、空白の位置に次の記号を描きます。

| 空白 | 記号 |
| --- | --- |
| 半角スペース（U+0020） | 点 |
| ノーブレークスペース類（U+00A0、U+2007、U+202F） | 点と、その上の山形 |
| 全角スペース（U+3000） | 四角 |
| タブ（U+0009） | 矢印 |
| その他の空白（U+2000〜U+200A、U+205F） | 二重線 |

記号を描く範囲は「空白を表示する範囲」で選べます。「すべて」（デフォルト）は本文のすべての空白、「選択範囲のみ」は選択している範囲の空白、「行末のみ」は改行の直前か段落の末尾まで続く空白に記号を描きます。折り返した位置は行末とみなしません。「選択範囲のみ」では、カーソルを動かしただけでは描き直しません。

改行と空白の記号は、テーマの`foreground`を30%の不透明度にした色で描きます。テーマになければ、`tertiaryLabelColor`で描きます。

### 7.2 番号

設定の「番号を表示」をオンにすると、本文の行頭の側の余白に番号を表示します。「番号の単位」が「段落」（デフォルト）なら、改行（LF、CR、U+2028、U+2029。CRLFは1つ）で区切った段落ごとに番号を振ります。「行」なら、折り返した行も含めて1行ごとに振ります。

番号は等幅の数字で、本文より1段階小さい文字サイズ（もっとも小さいサイズでは同じ大きさ）にし、`secondaryLabelColor`で描きます。横書きでは数字の高さの中央を行の中央にそろえ、縦書きでは本文の上の余白に90度回して描きます。本文が空でも「1」を表示します。

## 8 Markdownの記法の強調

設定の「Markdownの記法を強調する」がオン（デフォルト）のときは、Markdownの記法やHTMLの要素と読める部分の色、ウェイト、書体を変えて表示します。拡張子にかかわらずすべての書類が対象で、拡張子が`.mdx`ならMDXとして、それ以外はMarkdownとして読みます。原稿用紙のガイドでは強調しません。

強調は表示だけを変え、本文の文字は書き換えません。入力する文字には、記法の書式を引き継ぎません。記法はCommonMarkより緩く読み、複数の行をまとめて読むのは、コードブロックと先頭のFrontmatterだけです。

### 8.1 書式

記号は`secondaryLabelColor`で描きます。コードは等幅で、テーマの`palette`の2番（緑）、テーマになければ`systemGreen`（ライトモードでは暗くしたもの）で描きます。太字は、本文と同じ色の太字にします。

### 8.2 記法

| 記法 | 表示 | 1行目の字下げ |
| --- | --- | --- |
| Frontmatter（1行目が`---`だけの行で、`---`か`...`だけの行で閉じる。閉じなければFrontmatterとして読まない） | 記号の色、等幅 | しない |
| フェンスドコードブロック（行頭の空白はいくつでもよく、`` ` ``か`~`を3つ以上。閉じなければ本文の末尾まで） | フェンスは記号の色の等幅、中身はコード | しない |
| MDXの`import`と`export`の行（MDXのみ。行頭にあり、直後に空白かタブが続く行） | コード | しない |
| 引用（`>`） | `>`を記号の色 | する |
| テーブルの行（行頭が`\|`の行） | 区切りの`\|`を記号の色の等幅、区切りの行は全体を記号の色の等幅 | しない |
| 区切り線（`---`、`***`、`___`など） | 記号の色 | する |
| ATX見出し（`#`〜`######`） | `#`を記号の色の等幅、見出しの文字を太字 | しない |
| リスト（`-`、`*`、`+`、`1.`、`1)`）とタスクリスト（`[ ]`、`[x]`） | 記号を記号の色の等幅 | しない |
| インラインコード（同じ数の`` ` ``で囲む） | 囲みは記号の色、中身はコード | 行全体がコードならしない |
| 太字（`**…**`、`__…__`） | 囲みは記号の色、中身は太字 | する |
| リンクと画像（`[…](…)`、`![…](…)`、タイトルつきを含む） | 括弧とURLを記号の色 | する |
| HTMLのタグとコメント | 記号の色、等幅 | 行の最初と最後がタグならしない |

行頭の`|`を省いたテーブルは、テーブルとして読みません。太字の判定には、CommonMarkのflankingの規則を使いません。斜体（`*…*`）は表示を変えません。コードの中の記法は読みません。

## 9 テーマ

テーマは、本文の背景、文字、カーソル、選択範囲の色を決めます。設定の「テーマ」のペインで選び、選ぶとすぐに開いているすべてのウィンドウに反映します。「デフォルト」は初期値のテーマで、システムのライトモードとダークモードの色に従います。

Plainsongはプリセットのテーマを同梱していて、これらは[iTerm2-Color-Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes)（MIT License, Copyright (c) 2011 to Present Mark Badolato）のGhostty向けに配布されているファイルを使用しています。素敵なテーマを配布されている作者のみなさまと、テーマを集めて公開されているiTerm2-Color-Schemesに感謝します。また、いずれのテーマもMIT Licenseであり、著作権はそれぞれの作者にあります。

| テーマ | 作者 | 同梱しているテーマ |
| --- | --- | --- |
| [Catppuccin](https://github.com/catppuccin/catppuccin) | Catppuccin | Catppuccin Latte、Catppuccin Mocha |
| [Flexoki](https://github.com/kepano/flexoki) | Steph Ango | Flexoki Light、Flexoki Dark |
| [GitHub](https://github.com/primer/github-vscode-theme) | Primer | GitHub Light Default、GitHub Dark Default |
| [Iceberg](https://github.com/cocopon/iceberg.vim) | cocopon | Iceberg Light、Iceberg Dark |
| [Solarized](https://github.com/altercation/solarized) | Ethan Schoonover | Solarized Light、Solarized Dark |

### 9.1 テーマのファイル

テーマのファイルは、Ghosttyの設定ファイルと同じ書式のUTF-8のテキストとして読みます。`#`で始まる行は無視します。同じキーが複数あれば後の行を使い、空の値はそれまでの指定を取り消します。読むキーは次のとおりです。

| キー | 用途 |
| --- | --- |
| `background` | 本文とステータスバーの背景、ウィンドウのアピアランス |
| `foreground` | 文字の色。ガイドの線と、改行・空白の記号の色にも使う |
| `cursor-color` | カーソルの色、置換した箇所の下線の色 |
| `selection-background` | 選択範囲の背景の色 |
| `selection-foreground` | 選択範囲の文字の色 |
| `palette` | `palette = 2=…`の2番を、Markdownのコードの色に使う（0〜255を読む） |

色は16進数（`#`は省略でき、6桁か3桁で、引用符で囲んでもよい）だけを読み、X11の色名は読みません。ファイルにないキーと読めない値は、そのキーだけデフォルトの色を使います。背景色の明度（L\*）が50を超えればライト、そうでなければダークのアピアランスでウィンドウを表示します。選んでいたテーマのファイルが読めないときは、デフォルトの色で表示します。

### 9.2 テーマのペイン

一覧には、「デフォルト」、同梱のテーマ、区切り線、インポートしたテーマを、この順に並べます。テーマは名前順に並べ、区切り線はインポートしたテーマがあるときだけ表示します。VoiceOverでは、区切り線を「インポートしたテーマ」と読み上げます。各行には、背景色、文字色、カーソルの色で「Aa」とカーソルを描いた見本をつけます。「デフォルト」の見本は、左半分をライト、右半分をダークの色で描きます。行を選ぶとすぐにテーマを適用し、何も選んでいない状態にはできません。

一覧の下の「＋」（テーマをインポート）を押すと、ファイルを選ぶパネルを開きます。パネルでは、ファイルの種類で絞り込みません。複数のファイルを選べ、一覧にファイルをドラッグ＆ドロップしてもインポートできます。インポートしたテーマは、アプリケーションのフォルダにコピーします。同じ名前のテーマが（大文字と小文字を区別せずに）すでにあれば、「名前 2」のように番号をつけます。インポートを終えると、最後にインポートしたテーマを選びます。UTF-8で読めないファイルと、`background`、`foreground`、`cursor-color`、`selection-background`、`selection-foreground`のどれも読めないファイルはインポートせず、「テーマをインポートできませんでした」「次のファイルには、テーマとして使える色がありません：（ファイル名）」と知らせます。

インポートしたテーマを選んで「−」（テーマを削除）かdeleteキーを押すと、そのテーマを削除し、「デフォルト」に戻します。同梱のテーマは削除できず、選んでいるあいだは「−」を使えません。

一覧の下には、「Ghosttyのテーマと互換性があり、インポートして使用できます」の注記と、「謝辞」のリンクを置きます。「謝辞」のシートでは、感謝の意を示すメッセージ、同梱しているテーマごとの名前と作者（名前にテーマのプロジェクトへのリンクをつける）、テーマファイルの配布元へのリンクを表示します。シートは、「完了」ボタン（returnキー）、⎋キー、⌘.で閉じます。

## 10 検索と置換

### 10.1 パネル

検索と置換は、本文のウィンドウとは別のパネルで行います。「検索…」（⌘F）で検索のモード、「検索と置換…」（⌥⌘F）で置換のモードのパネルを開きます。パネルの上部のセグメンテッドコントロールでも、モードを切り替えられます。置換の欄は、置換のモードでだけ表示します。

パネルは、初めて開いたときは本文のウィンドウの右上付近に置き、その後は位置を記憶します。常に手前に表示されるフローティングパネルではなく、通常のウィンドウと同じように扱います。全画面表示の本文のウィンドウの上にも表示でき、「ウインドウ」メニューにも載ります。パネルのアピアランスと背景色は、検索している本文のウィンドウのテーマに合わせます。⎋キーで閉じ、閉じると一致箇所のハイライトを消します。

検索の対象は、常にメインウィンドウの本文です。メインウィンドウが変われば、検索の対象も切り替わります。

| 要素 | 内容 |
| --- | --- |
| 検索の欄 | 検索語。入力が200ms止まると探し直す。returnで次を、shift+returnで前を検索する |
| 置換の欄 | 置換の文字列。正規表現では`$1`などのテンプレートを使える。returnで「置換して次を検索」を行う |
| 大文字/小文字を区別 | デフォルトはオフ |
| 全角/半角を区別 | デフォルトはオン。正規表現では常に区別し、チェックボックスはオンの表示のまま使えなくなる |
| 正規表現を使用 | デフォルトはオフ。`^`と`$`は各行の先頭と末尾に一致する |
| 末尾に到達したら先頭へ戻る | デフォルトはオン |
| 前を検索・次を検索 | 前後の一致箇所を選ぶ |
| 件数 | 「（総数）件中（番号）件目」「（総数）件」「見つかりません」「正規表現の誤り」のいずれか |
| 次を検索（検索のモード） | 次の一致箇所を選ぶ |
| 置換して次を検索（置換のモード） | 選んでいる一致箇所を置換し、次の一致箇所を選ぶ。一致箇所を選んでいなければ、次の一致箇所を選ぶだけ |
| すべて置換 | 「置換して次を検索」のボタンのメニューの中に置く |
| 結果 | 検索や置換の結果をアイコンと文で表示する（[10.3節](#103-置換)） |

4つのチェックボックスの状態は保存し、次に起動したときも使います。検索語はアプリケーションに保存せず、システムの検索用ペーストボードで他のアプリケーションと共有します。パネルを開くときと、パネルを閉じたまま「次を検索」「前を検索」「検索結果をすべて選択」を使うときに、他のアプリケーションで検索した語があれば読み込みます。パネルを閉じていても、検索語があれば「次を検索」「前を検索」「検索結果をすべて選択」を使えます。

正規表現に誤りがあるときは、VoiceOverとツールチップで「正規表現が正しくありません」と伝えます。

### 10.2 検索

一致箇所にはすべて、選択範囲の色を45%の不透明度で重ねます。選択範囲とぴったり重なる一致箇所を、いま選んでいる一致箇所とみなします。パネルを開いたときと、検索語、モード、「大文字/小文字を区別」「全角/半角を区別」「正規表現を使用」を変えたときは、選択範囲の位置から後ろで最初の一致箇所を選び、後ろになければ先頭の一致箇所を選びます。次（前）の一致箇所がなく、先頭へ戻らない設定なら、ビープ音を鳴らします。本文を編集すると、100ms後に探し直します。検索の欄の入力が止まる前にreturnやボタンを押したときは、待たずに探し直し、そこで見つかった一致箇所を選びます。

見つかった箇所がパネルに隠れるときは、本文をスクロールします。スクロールしても隠れるときは、パネルを画面の中で動かします。

### 10.3 置換

1件ずつ置換していく操作は、始めた箇所まで一周するか、末尾で止まったところで終わります。続けて置換しているあいだは、置換した箇所にカーソルの色の下線（縦書きでは傍線）を引き、一致箇所から外します。置換したあとの文字列に検索語が含まれていても、その箇所は選び直しません。置換した箇所をさらに書き換えると、その箇所は置換した記録から外れます。一周したあとも続けて置換するときは、置換した箇所を覚えたまま、その位置からもう一周します。検索語、置換の文字列、モード、「末尾に到達したら先頭へ戻る」以外のオプションのどれかを変えると、続けての置換を終えます。「すべて置換」では、続けて置換した箇所を重ねて置換しません。

結果は次のように表示し、VoiceOverでも読み上げます。

| 状況 | 表示 | アイコン |
| --- | --- | --- |
| 先頭へ戻らない設定で、前へ戻って先頭の一致箇所に着いた | 先頭まで検索しました | 警告 |
| 先頭へ戻らない設定で、末尾の一致箇所に着いた | 末尾まで検索しました。置換していれば「末尾まで検索して、（件数）件を置換しました」 | 置換していなければ警告、していれば完了 |
| 一周した | 置換していれば「（件数）件を置換しました」、していなければ「ひと通り検索しました」 | 完了 |
| すべて置換した | （件数）件を置換しました | 完了 |

置換は取り消せます。取り消しの操作名には「置換」「すべて置換」を使います。

## 11 ツールバーとステータスバー

ツールバーとステータスバーに表示する項目は、設定の「機能拡張」で選べます。デフォルトでは、どちらの項目もすべてオフです。

### 11.1 ツールバー

ツールバーの項目は、アイコンだけで右寄せに並べます。macOS標準のツールバーのカスタマイズはできません。

| 項目 | SF Symbols | 動作 |
| --- | --- | --- |
| コピー | `doc.on.doc` | 全文をクリップボードへコピーする |
| 検索 | `magnifyingglass` | 検索のパネルを開く |
| 保存 | `square.and.arrow.down` | 「保存」と同じく、ファイルへ保存する |
| 共有 | `square.and.arrow.up` | 全文を共有メニューで共有する |
| 削除 | `trash` | 全文を削除して空にする |

コピー、共有、削除には、「テキストを選択中は、選択したテキストのみコピーする」（共有する、削除する）のオプションがあります。オン（デフォルト）なら、テキストを選択しているときは、選択したテキストだけを対象にします。複数の範囲を選んでいるときの共有は、範囲を改行でつないだテキストにします。検索には、「テキストを選択中は、選択したテキストを検索する」（デフォルトはオン）と「置換を開く」（デフォルトはオフ）のオプションがあります。前者がオンなら、選択したテキストを検索語にしてからパネルを開きます。後者がオンなら、置換のモードでパネルを開きます。

全文の削除は、キー入力と同じく取り消しの履歴に入り、⌘Zで取り消せます。コピーと削除のあとは、VoiceOverで「コピーしました」「削除しました」と読み上げます。

### 11.2 ステータスバー

ステータスバーは、本文のウィンドウの下端に重ねる高さ32ptの帯です。左に項目を並べ、右端に設定ウィンドウを開く歯車のボタンを置きます。項目の左端と歯車のアイコンの右端は、横書きでは本文の行頭と行末に、縦書きでは左右の余白にそろえます。項目がなく、歯車のボタンも表示しないときは、ステータスバーを表示しません。

| 項目 | 表示 |
| --- | --- |
| 文字数 | 「（数）文字」。選択中は「（数）文字（（数）文字を選択中）」 |
| 単語数 | 「（数）単語」。選択中は「（数）単語（（数）単語を選択中）」 |
| 原稿用紙の枚数 | 「（数）枚」。選択中は「（数）枚（（数）枚を選択中）」 |
| 文字エンコーディング | ファイルの文字エンコーディング（[3.4節](#34-文字エンコーディング)の表示名）。下書きはUTF-8 |
| 改行コード | `LF`、`CRLF`、`CR`。下書きはLF |

ステータスバーの背景（本文の背景色と、上端の区切り線）は、本文の文字がステータスバーの帯まで届いたときだけ表示します。「ポインタを重ねたら表示」がオンなら、ポインタを重ねたときだけ項目と背景を表示し、隠れているあいだはクリックを本文に通します。表示の切り替えは、0.15秒でフェードします。ステータスバーの上でスクロールすると、本文がスクロールします。項目が入りきらないときは、ウィンドウを広げずに、後ろの項目から省略します。項目の文字は、選択してコピーできます。

変換中の文字があるあいだは、確定するまで数え直しません。1回の操作で何度編集したり選択を変えたりしても、数えるのは1回です。数は段落ごとに覚えておき、編集した段落だけを数え直します。複数の範囲を選んでいるときは、それぞれの範囲の数を足します。

### 11.3 文字数

Unicodeの書記素クラスタ（UAX #29）を1文字として数えます。CRLFと、対になっていないサロゲートも1文字です。空白に結合文字が続くと、空白ではない1文字として数えます。オプションで、半角スペース（デフォルトはオン）、全角スペース（オン）、タブ（オフ）、改行（オフ）を、文字数に含めるかどうかを選べます。

### 11.4 単語数

単語の数え方は、オプションで次の3つから選べます。

- 「macOS標準の区切り方で数える」（デフォルト）は、Natural Languageフレームワークの単語の区切りで数えます。日本語や中国語は、辞書を使って単語に分けます
- 「日本語と中国語は1文字を1単語として数える」は、Microsoft Wordに近い数え方です。漢字、ひらがな、カタカナ（半角を含む）、`々〆〇`を含む語は1文字を1単語とし、英語や韓国語は単語ごとに数えます
- 「アルファベットの単語のみ数える」は、ラテン文字（半角・全角の英字、アクセント記号の付いた文字など）を含む語だけを数えます。数字だけの語は数えません

### 11.5 原稿用紙の枚数

400字詰め（20字×20行）の原稿用紙に書いた場合の枚数を表示します。行は原稿用紙の組み方（[6.3節](#63-原稿用紙)）で数えますが、画面のマスの数にかかわらず、1行を20字とします。字下げとぶら下げの設定も反映します。20行で1枚と数えます。選択中の枚数は、選択した範囲の行数を枚数に直したものです。

### 11.6 機能拡張のペイン

設定の「機能拡張」のペインには、「ツールバー」と「ステータスバー」の2つの一覧を置きます。各行には、並べ替えのハンドル、アイコン（ツールバーのみ）、名前と説明、「設定…」ボタン（オプションがある項目のみ）、表示を切り替えるスイッチを並べます。

| 一覧 | 項目と説明（初期の並び順） |
| --- | --- |
| ツールバー | コピー（クリップボードへコピーします）、検索（テキストを検索します）、保存（ファイルへ保存します）、共有（共有メニューを開きます）、削除（入力した内容を削除して空にします） |
| ステータスバー | 文字数（テキストに含まれる文字を数えます）、単語数（テキストに含まれる単語を数えます）、原稿用紙の枚数（400字詰めの原稿用紙に書いた場合の枚数を表示します）、文字エンコーディング（ファイルの文字エンコーディングを表示します）、改行コード（ファイルの改行コードを表示します） |

項目は、ドラッグ＆ドロップか、行を選んで⌥⌘↑・⌥⌘↓を押して並べ替えます。コンテキストメニューの「上に移動」「下に移動」「先頭に移動」「末尾に移動」でも並べ替えられ、動かせない方向のメニュー項目は使えません。VoiceOverでは、カスタムアクションの「上に移動」「下に移動」で並べ替えます。行を選んでスペースキーを押すと、表示を切り替えます。保存した並びにない項目は、初期の並びで1つ前にある項目のすぐ後ろに入れます。

「設定…」ボタンで開くシートに、各項目のオプション（[11.1節](#111-ツールバー)、[11.3節](#113-文字数)、[11.4節](#114-単語数)）を置きます。文字数のシートには「Unicodeの書記素クラスタ（UAX #29）に基づいて数えます」と注記し、単語数のシートでは選択肢ごとに説明をつけます。シートは、「完了」ボタン（returnキー）、⎋キー、⌘.で閉じます。

ステータスバーの一覧の下には、「設定ボタンを表示」（デフォルトはオン）と「ポインタを重ねたら表示」（デフォルトはオフ）のチェックボックスを置きます。

## 12 印刷

「プリント…」（⌘P）を選ぶと、本文を用紙に合わせて組み直して印刷します。文字は黒で印刷し、テーマの色、番号、改行と空白の記号、Markdownの記法の強調、検索のハイライトは印刷しません。用紙の方向は、横書きなら縦、縦書きなら横を初期値にします。

プリントパネルでは、部数、ページの範囲、用紙サイズ、方向、拡大縮小を選べ、プレビューも確認できます。さらに「Plainsong」の項目で、次のオプションを選べます。

| オプション | 表示する条件 | 初期値 |
| --- | --- | --- |
| 罫線を印刷 | ガイドが罫線 | オン |
| マス目を印刷 | ガイドが原稿用紙 | オン |
| ページ番号を印刷 | 常に | ガイドが原稿用紙ならオン、それ以外はオフ |

ページ番号は、ページの下の余白の中央に印刷します。ガイドの線は、画面の線の濃さを白い紙の上で再現したグレーを使い、0.5ptの太さで印刷します。

### 12.1 白紙と罫線

設定の文字サイズ、行間、フォント、組方向、カーニング、段落の間の余白、字下げ、ぶら下げで組みます。行の長さは、用紙の印刷できる範囲の幅（縦書きでは高さ）です。ぶら下げがオンなら、行頭と行末に1字分ずつ空けます。ページは行の単位で分け、末尾の改行のあとの空の行だけのページは作りません。罫線は行と行のあいだに引き、本文の末尾より先も用紙の端まで引きます。縦中横の数字はグリフのアウトラインで描き、PDFのテキストに数字が重複して残らないようにします。

### 12.2 原稿用紙

画面のマスの数にかかわらず、1ページを400字詰め（20字×20行）にします。マスの大きさは、行の方向に21マス（ぶら下げる句読点の分の1マスを含む）が入る大きさと、行と交わる方向にマスの1.4倍の行送りで20行が入る大きさの、小さいほうです。文字はマスの0.72倍の大きさで、1字ずつマスの中心に置きます。マス目は、列ごとの閉じた長方形と、マスを区切る線で描きます。

## 13 設定ウィンドウ

設定ウィンドウには「一般」「テーマ」「機能拡張」の3つのペインがあり、ウィンドウのツールバーで切り替えます。最後に選んだペインと、ウィンドウの位置を記憶します。大きさはペインの内容で決まります。タイトルは選んでいるペインの名前で、「ウインドウ」メニューでは「設定 — 一般」のように表示します。⎋キーと⌘.で閉じます。開くときは、メニューバーのアイコンのメニューから開いたときも含めて、アプリケーションをアクティブにします。

設定は、変えるとすぐに保存し、開いているすべてのウィンドウに反映します。テーマのペインは[9.2節](#92-テーマのペイン)、機能拡張のペインは[11.6節](#116-機能拡張のペイン)で説明します。

## 15 コマンドラインツール

### 15.1 songコマンド

`song`は、アプリケーションのバンドルの`Contents/SharedSupport/bin/song`に同梱しているシェルスクリプトで、`song [file ...]`の形で使います。

| 呼び出し | 動作 |
| --- | --- |
| `song` | Plainsongを起動する |
| `song file ...` | ファイルをPlainsongで開く。存在しないファイルは、空のファイルを作ってから開く |
| `song -h`、`song --help` | 使い方を表示する |
| `song -v`、`song --version` | アプリケーションの`Info.plist`から読んだバージョンを、`Plainsong 1.5.0`のように表示する |
| `song -- -file` | `--`より後ろは、`-`で始まる名前もファイルとして扱う |

エラーは、先頭に`song: `をつけて標準エラー出力に書き出します。不明なオプションを指定すると`unknown option: …`と`Run 'song --help' for usage.`を表示し、終了コード2で終わります。フォルダを指定したとき（`can't open a folder: …`）、親フォルダがないとき（`no such folder: …`）、ファイルを作れないとき（`can't create a file: …`）は、終了コード1で終わります。

シンボリックリンクから呼び出されても、リンク先をたどってスクリプトを含むアプリケーションを見つけ、`open -a`でそのアプリケーションを指定して開きます。

### 15.2 コマンドラインツールのウィンドウ

アプリケーションのメニューの「コマンドラインツール…」で開きます。アプリケーションのアイコン、見出し「songコマンド」、説明「Plainsongをコマンドラインから起動したり、ファイルを開けるsongコマンドを利用できます。コピーしてコマンドラインで実行してください。」を表示し、その下の「インストール」と「アンインストール」の欄に、それぞれのコマンドと「コピー」ボタンを置きます。

インストールのコマンドは`sudo mkdir -p /usr/local/bin && sudo ln -si <songのパス> /usr/local/bin/song && song --help`です。パスは必要に応じて、シェルの引用符で囲みます。すでに`song`があれば、置き換える前に確認を求めます。アンインストールのコマンドは`sudo rm /usr/local/bin/song`です。

「コピー」を押すと、コマンドをクリップボードにコピーし、2秒間「コピーしました」と表示して、VoiceOverでも読み上げます。VoiceOverでは、2つのボタンを「インストールのコマンドをコピー」のように区別して読み上げます。コマンドの文字は選択できます。⎋キーで閉じ、状態の復元では開き直しません。

## 16 アクセシビリティ

画面にタイトルを表示しないウィンドウ（下書き、検索と置換のパネル、コマンドラインツール）にもタイトルをつけ、VoiceOverで読み上げ、「ウインドウ」メニューにも表示するようにしています。ラベルのないコントロール（ポップアップボタン、スライダー、セグメンテッドコントロール、検索の欄など）にはアクセシビリティラベルをつけ、装飾のアイコンはVoiceOverの対象から外しています。操作の結果は、画面の表示に加えてVoiceOverで読み上げます（[10.3節](#103-置換)、[11.1節](#111-ツールバー)、[15.2節](#152-コマンドラインツールのウィンドウ)）。アクセシビリティの「コントラストを上げる」がオンなら、ガイドの線を濃くします（[6.1節](#61-線の描き方)）。

### 17.2 下書きの保存形式

下書きのフォルダには、全文を収めた`text.txt`（スナップショット、UTF-8）と、編集の差分を記録する`journal`（ジャーナル）を置きます。

編集のたびに、差分をジャーナルへ追記します。入力が2秒止まると、ジャーナルをディスクまで書き出します（`F_FULLFSYNC`、使えなければ`fsync`）。アプリケーションがアクティブでなくなったときと下書きを閉じたときは、全文を一時ファイルに書いてスナップショットと入れ替え、そのあとジャーナルを空にします。ジャーナルへの追記に失敗したときは、次の機会に全文を書き直します。

ジャーナルの先頭には、元にしたスナップショットのハッシュ（FNV-1a、64bit）を置き、そのあとにレコードが続きます。レコードは、チェックサム、置き換えた位置、削除した長さ、挿入した長さ（それぞれ32bit）と、挿入した文字列からなります。位置と長さはUTF-16の単位で数え、文字列もUTF-16で格納します。

下書きを開くときは、スナップショットにジャーナルを再生して内容を復元します。ジャーナルのハッシュがスナップショットと一致しなければ、差分はすでにスナップショットに含まれているものとして再生しません。壊れたレコードがあれば、そこで再生を止めて読めたところまでを使い、続きをそこから記録します。スナップショットに壊れたバイトがあっても、読めるところは残します。
